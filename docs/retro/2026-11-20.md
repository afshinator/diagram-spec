# Retro — 2026-11-20 (diagram-spec v1 build + 8 triage tickets)

Session: 22:52 → 02:16 (3h24m), 27 user turns, 533 tool calls, 45 error-bearing results.
Scope: built v1 core, then worked tickets #1–#8 to closure, merged to `main`.

## Findings, by severity

### 1. No guardrail exists — `bun run check` is a voluntary act (high)

`package.json:15` defines `check` = `typecheck && test && generated drift && fallow audit`,
which is a genuinely good gate. Nothing runs it. No `.github/` workflow, no active
`.git/hooks` entry, no pre-push hook.

Consequence in this session: `bun run check` was invoked 36 times because the agent
chose to, and at least four commits were only correct because it ran afterwards — the
`generated/` drift check in #8 caught a stale committed DSL that no test would have.
A future run that skips it ships the defect.

Fix: a CI workflow on push and pull request running `bun run check`. Filed as #9.

### 2. Adapter capability knowledge was re-derived three times (high)

Measured cost: 29 bash calls invoking `d2` or `mmdc`, and the string
`shape: sequence_diagram` written 48 times in the transcript. The findings that
mattered (phantom participant columns, `group:` vs `span:`, frontmatter must be line 1,
`Note over A,B` max two) were re-discovered by hand each time they came up.

Worse, the knowledge was only durable at the *end*: `docs/adapter-findings.md` was
written after tickets #5–#7. When it was finally written it forced a re-measurement,
which showed an earlier claim was wrong — I had recorded the loop evidence with
`span:`, which is not a sequence keyword and produces the very phantom column the
ticket was about. Had the measurement been a runnable artifact from the start, that
error would have been caught at the point of writing instead of after committing.

Fix: commit the probe as executable code (a `bun run probe` script writing fixture
`.d2`/`.mmd`, rendering, asserting lifeline and actor-row counts), so the next run
measures instead of reading prose. Filed as #10.

### 3. `AGENTS.md` points at triage docs but not at the two files that answer real questions (medium)

`AGENTS.md` is 14 lines and every line is a pointer — good shape. But it points only at
`docs/agents/*` (issue tracker, labels, domain). It does not name `bun run check`, nor
`docs/adapter-findings.md`, nor `docs/BUILD_PROMPT.md`.

The cost is measurable: the agent read `docs/BUILD_PROMPT.md` and
`docs/diagram-spec-bootstrap.md` from scratch, and rediscovered the `check` script by
reading `package.json`. Both are exactly the lookups a pointer retires.

Fix: three pointer lines. Filed as #11 (with the `.gitignore` finding, same one-line
neighbourhood).

### 4. `.scratch/` was not gitignored while `.tmp/` was (medium)

`.gitignore` lists `.tmp/` but not `.scratch/`. The session wrote 30+ fixtures to
`.scratch/` early on, all untracked and sweepable. One stray file (`n.d2n$`, from a
typo'd `printf`) did survive into the working tree and was only removed during #7.

Fix: add `.scratch/` to `.gitignore`, or standardise on `.tmp/` alone. In #11.

### 5. `gh issue create -b` with a long quoted body fails (low, cross-repo)

10 `gh issue create` invocations; the first failed with
`unknown shorthand flag: 'o' in -o`, then the `--body-file` form worked every time.
The durable lesson is not diagram-spec specific: write the body with the write tool to
`.tmp/issue-N.md` and pass `--body-file`. Recorded here; kept out of the global
`AGENTS.md` because it is one command's flag behaviour, not a standing rule.

### 6. Harness blocks fire as designed but cost 13 calls (low, no action)

13 blocked calls: 4 shell file slices, 4 in-place rewrites, 3 interpreter rewrites,
2 file-writing heredocs. Each block is correct — the mutations would have been rejected
by the rule anyway — so this is the rules working. The only slack is that the positive
target could be stated once: *scratch scripts go in `.tmp/`, written with the write
tool*. Left as a note; the global file already carries the negative, and adding the
positive is not worth a line there.

## Explicit non-findings

- **`CODING_STANDARDS.md` is not warranted.** No mechanical violation recurred: no
  repeated import shape, no banned API, no file-location mistake. The one repeated
  mistake class (generated-file drift) is already deterministic, and #9 wires it.
  Adding a standards file here would be sediment.
- **The global `AGENTS.md` is not too large** (29 lines) and every rule observed fired
  at least once.
- **No information-access gap.** `d2`, `mmdc` and the local Chrome were all reachable;
  nothing sat behind a service the agent could not read.
