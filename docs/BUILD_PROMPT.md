## Hard rules

- The core is **model-free and network-free**: no LLM call, no fetch, no telemetry, no postinstall
  script. §13.8 and §14 require this and it is the whole point of the tool.
- `dspec validate` completes in **< 100 ms** and prints human-readable `path + reason` errors only.
- `dspec emit` is **deterministic**: unchanged input produces byte-identical output (§13.5). Sort
  everything you iterate.
- The schema is **generic**. Never hardcode a project's vocabulary, actor names or event names (§4,
  §14). Vocabulary is declared inside each `diagram-content.yaml`.
- All rules live in the core. The skill may invoke the CLI and block on its result; it must never
  restate a rule (§2 boundary rule, §13.10).
- No new dependency unless an adapter needs it. zod is approved; everything else needs a reason in
  the commit message.
