# Domain documentation

This is a single-context repository.

Before exploring domain behavior:

1. Read `GLOSSARY.md` if it exists.
2. Read relevant ADRs under `docs/adr/` if they exist.
3. Use the glossary's terms in issue titles, tests and implementation notes.
4. Surface conflicts with existing ADRs instead of silently overriding them.

The glossary and ADRs are created lazily when domain terms or decisions need to
be recorded.
